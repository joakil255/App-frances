# Etapa 9 — Chat de voz en francés: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Voz dentro de «Conversar»:
- micrófono con el reconocimiento del navegador (`fr-FR`), cuyo resultado queda en el campo para revisarlo;
- «Escuchar primero», con la respuesta leída sola y su texto tapado;
- botones para volver a oír la respuesta (normal y lenta) y la forma correcta de cada corrección;
- aviso de privacidad la primera vez.

**Architecture:**
- Lógica pura y probada en `js/lib/recognition.js` (reconocimiento) y `js/lib/voice-settings.js` (ajustes guardados).
- El micrófono y el aviso de privacidad, en `js/screens/chat-voice.js`.
- «Escuchar primero» y los botones de escucha, en `js/screens/chat.js`, reutilizando `playFrench` de `js/screens/voice.js`.
- El servidor no cambia.

**Tech Stack:** JS en módulos sin dependencias nuevas, Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`, `speechSynthesis`), `localStorage`, `node --test` y ESLint.
**Spec:** `docs/superpowers/specs/2026-11-24-etapa-9-voz-design.md` + `DESIGN.md`

## Global Constraints
- **TDD estricto:** primero la prueba, verla fallar y luego el código mínimo. Nunca se debilita ni se borra una prueba.
- **Git solo local:** rama `etapa-9-voz`, commits pequeños en español, cada uno terminado en `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. **Sin `git push` ni cambios en GitHub Pages sin la confirmación del usuario.**
- **Sin dependencias nuevas** y **sin proveedores de audio** distintos del navegador. **El servidor (`server/`) no se toca.**
- Todo texto reconocido, escrito o de Claude se pinta con `textContent`; nunca `innerHTML`. Textos visibles en español, código en inglés, comentarios breves en español.
- Valores del diseño:
  - reconocimiento con `lang = 'fr-FR'`, `interimResults = true`, `maxAlternatives = 1` y `continuous = false`;
  - campo de 500 caracteres como máximo, contados por letra (`[...text].length`);
  - velocidades `RATES.normal` y `RATES.slow` de `js/lib/speech.js`.
- Clave nueva `app-frances-voice` → `{ schemaVersion: 1, listenFirst, privacyAccepted }`; si falta o está dañada, `{ listenFirst: true, privacyAccepted: false }`. Va **fuera** de la copia de seguridad: `backup.js` no cambia. `app-frances-chat` no cambia de formato.
- `sw.js`: `CACHE_VERSION = 'v18'`, y cada archivo nuevo de la app va en `PRECACHE_URLS` en la tarea que lo crea.
- Los agentes no hacen pruebas en dispositivos reales ni llamadas reales a Claude: eso lo hace el controlador con el usuario (Tarea 5).

## Review Focus
1. **Escribes mientras el micrófono escucha:** al llegar el resultado final se agrega al texto **actual** del campo, no a una copia de antes, y no se pierde nada (Tarea 1, pruebas de `appendTranscript`; Tarea 4, el resultado final usa `field.value` del momento; recorrido).
2. **«Escuchar primero» sin voz francesa o con el motor fallando:** el texto de la respuesta aparece solo y el aviso sale una vez (Tarea 3: `playFrench` llama a `onFail`; recorrido con un `speechSynthesis` falso sin voces).
3. **Permiso del micrófono negado** (`not-allowed`): aparece `micBlocked` y el botón vuelve a «Hablar» con `aria-pressed="false"` (Tarea 1: `startListening` llama a `onEnd` también tras un error; Tarea 4, recorrido).
4. **Tocar el micrófono sin conexión:** aparece `chatOffline` y el reconocimiento no se inicia (Tarea 4, recorrido).
5. **Tocar «Hablar» dos veces o «Enviar» mientras escucha:** nunca hay dos reconocimientos a la vez, y enviar detiene el micrófono (Tarea 1: `stop()`; Tarea 4, recorrido).

### Task 1: Lógica del reconocimiento y ajustes de voz (TDD)
**Files:** Create `js/lib/recognition.js`, `js/lib/voice-settings.js`, `tests/recognition.test.js`, `tests/voice-settings.test.js`. Modify `sw.js` (`v18` y los dos archivos nuevos).
**Consumes:** `toStorageError` de `js/lib/storage.js`.
**Produces:**
- `getRecognitionConstructor(win): Function | null`: `win.SpeechRecognition`, si no `win.webkitSpeechRecognition`, si no `null`.
- `appendTranscript(current: string, transcript: string, max = 500): string`.
- `recognitionMessageKey(error: string): string | null`.
- `startListening({ Recognition, onInterim(text), onFinal(text), onError(code), onEnd() }): { stop() }`.
- `VOICE_KEY = 'app-frances-voice'` y `createVoiceStore(backend): { load(): { listenFirst, privacyAccepted }, save({ listenFirst, privacyAccepted }) }`. `save` lanza `StorageError` (con `toStorageError`); `load` nunca lanza.

**Tabla de `recognitionMessageKey`:**

| Código de error | Clave del mensaje |
|---|---|
| `not-allowed`, `service-not-allowed` | `micBlocked` |
| `no-speech` | `micNoSpeech` |
| `audio-capture` | `micNoDevice` |
| `network` | `micNetwork` |
| `language-not-supported` | `micLanguage` |
| `aborted` | `null` (sin mensaje) |
| cualquier otro | `micFailed` |

### Task 2: Mensajes del micrófono (TDD)
**Files:** Modify `js/lib/messages.js`, `tests/messages.test.js`.
**Produces:** las claves de `MESSAGES` de la tabla siguiente. Las pantallas las usan con `MESSAGES[recognitionMessageKey(code)]`.

| Clave | title | text |
|---|---|---|
| `micBlocked` | El navegador no deja usar el micrófono. | Permite el micrófono para este sitio en los ajustes del navegador (el candado junto a la dirección) y vuelve a tocar Hablar. |
| `micNoSpeech` | No se oyó nada. | Toca Hablar y di tu frase cerca del micrófono. |
| `micNoDevice` | No se encontró un micrófono. | Revisa que el dispositivo tenga micrófono y que ninguna otra app lo esté usando. |
| `micNetwork` | No se pudo conectar con el reconocimiento de voz. | Revisa tu conexión y vuelve a intentarlo, o escribe tu mensaje. |
| `micLanguage` | Este navegador no reconoce voz en francés. | Escribe tu mensaje: el resto de la pantalla funciona igual. |
| `micFailed` | El reconocimiento de voz falló. | Vuelve a tocar Hablar o escribe tu mensaje. |

- [ ] **Paso 1:** añadir las 6 claves a `KEYS` (pasan por las pruebas de «terminan en punto» y «no se disculpan») y la prueba `'los mensajes del micrófono tienen su texto exacto'` (`deepEqual` con la tabla).
- [ ] **Paso 2:** ver que fallan. **Paso 3:** implementar. **Paso 4:** pruebas y linter. Commit `feat: mensajes de error del micrófono`.
